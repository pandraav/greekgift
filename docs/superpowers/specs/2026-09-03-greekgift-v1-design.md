# greekgift v1 — design spec (skeleton and shared contracts)

> Status: SKELETON. Sections 5–8 are written by four independent agents against
> the contracts in section 4, verified, then merged here. Everything in sections
> 1–4 is fixed and must not be changed by section writers.

## 1. What greekgift is

A free chess game reviewer for a small group of friends. You enter a chess.com
username, pick a game, and get everything chess.com's Game Review gives you:
ten move classifications, accuracy, estimated rating, eval graph, engine lines,
a variation tree, key-moment walkthrough with hint / show best / retry, and a
coach whose explanations are generated by an LLM through OpenRouter but grounded
in verified facts. Analysis runs in the browser with a fixed node budget so the
numbers are identical on every device. Results are stored in Postgres keyed by
username so the next viewer skips the engine and sees the same numbers.

Hobby project. No accounts, no billing, no legal posture, no competing-with-
chess.com concerns. Own glyphs, colours, piece set and coach avatar.

## 2. Decisions already made (do not reopen)

| Decision | Choice |
|---|---|
| Entry point | chess.com username only (v1). PGN paste and lichess are later. |
| Engine | Stockfish 18 WASM, single-threaded build, N Web Workers in the browser. No server engine in v1. |
| Determinism | Every search is `go nodes <N>` with `Threads 1`, `Hash 16`. Same build + same nodes = same eval everywhere. Never `movetime`. |
| Coach | OpenRouter via Vercel AI SDK OpenAI-compatible provider. Model from `OPENROUTER_MODEL` env. Renders facts only; validated before display; template fallback. |
| Persistence | Neon Postgres via Drizzle. Reviews keyed by chess.com username + game id and shared by all signed-in users. Position evals cached by FEN + node budget + engine build. |
| Auth | Better Auth (`better-auth`) with the Drizzle adapter, email + password only. Sign-up is **invite-by-approval**: anyone can submit the sign-up form (name, email, **occupation**, password + confirm, short note — **not** a chess.com username; that moved to `/settings`, because reviews are keyed by username rather than by account and it is only needed when someone runs one), which creates a user with `status = 'pending'` and sends a verification email. Unverified users cannot sign in. Verified pending users can sign in but see only `/pending` ("awaiting approval"). Admins (emails listed in `ADMIN_EMAILS`, given `role = 'admin'` on first sign-in) approve or reject from `/admin`; approval flips `status` to `'approved'` and unlocks the whole app. Rejected users see `/pending` with a rejected message. Every other page and route handler requires an approved session. Transactional email goes through Brevo (see Email row). Each user's chess.com username from sign-up is stored as their linked username (a "my games" shortcut, editable in `/settings`); linking does not restrict what others can view. |
| Email | Brevo transactional email via its REST API (`@getbrevo/brevo` SDK or plain `fetch` to `https://api.brevo.com/v3/smtp/email`), key in `BREVO_API_KEY`, sender in `EMAIL_FROM`. Three emails, all plain HTML templates in `packages/email`: (1) verify your address on sign-up (Better Auth `emailVerification`, required before sign-in), (2) approval notice when an admin approves, (3) password reset (Better Auth `sendResetPassword`). Rejections send no email. Brevo free tier is 300 emails/day, which is far above expected volume. |
| Env validation | `@t3-oss/env-nextjs` with `zod`. One `apps/web/src/env.ts` defines every variable; the app imports `env` from it and never touches `process.env` directly. All variables are **required** (no defaults, no optionals) so a missing key fails the build, not a request at 2am. Validation runs at build and at server start; `SKIP_ENV_VALIDATION=1` is allowed only for Docker-style builds and CI lint. |
| Coach personas | **Seven** voices modelled on well-known chess creators. **This row is superseded by `2026-09-04-coach-personas.md`**, which is authoritative: Naroditsky was removed and the default is now Sagar Shah (The Mentor); six of the seven style names differ from the list once written here. Full definitions — voice rules, lexicons, budgets, exemplars and rendered examples — live in `docs/superpowers/specs/2026-09-04-coach-personas.md` and are implemented verbatim in `packages/coach/personas.ts`. Each carries `id`, `displayName` and `homage`; renaming to non-attributed archetypes before any public launch is a one-line change per persona, because the display name, not the voice, is what carries publicity-rights risk. Chosen globally in `/settings`, changeable inside a review; never adapts automatically. |
| Coach pipeline | Three stages, not two: engine → **content selection (deterministic code)** → **rendering (LLM, words only)**. Content selection decides which facts are mentioned, in what order, at what depth, from the player's rating. The persona never sees the raw facts object, because persona prompting measurably shifts what a model prioritises, so a two-way split leaks voice into fact selection. |
| Coach depth by rating | ≤1000: directive, 3–5 moments per game maximum, silence elsewhere, defines terms like fork, never shows centipawns or engine lines. 1000–1500: 5–8 moments, elaboration on request. 1500+: facilitative, user-driven, never explains what a fork is. Redundant explanation costs a stronger player working memory rather than merely boring them. |
| Coach safety rules | R1 use only facts in the object; R2 **no chess notation in prose** (bare squares and spoken forms like "the knight takes on d7" are allowed; formal notation comes only from fixed schema slots); R3 never describe more follow-up moves than the engine line contains; R4 mock the move, the square or chess itself, never the individual player; collective ribbing ("everyone plays this") is allowed, comments on this player's ability are not; R5 praise the move, never the person; R6 if a fact is absent, say nothing rather than guess. R4 is what keeps The Grump shippable. |
| Coach output schema | Fixed slots in this order: `reasoning` (scratchpad, first — field order changes accuracy substantially), `headline`, `what_happened`, `why_it_matters`, `better_was`, `lesson`; all marked required. Load-bearing chess tokens are pinned per move with JSON-schema `const`, so `better_was` is a copy operation rather than a generation and cannot hallucinate. |
| Coach validation | Deterministic gate: extract SAN tokens, squares and numerals from prose; assert the SAN set is empty (R2 makes this trivial), squares are a subset of those in the facts, numerals are a subset of the facts' numbers. On failure, retry once with the error, then fall back to the template coach. The failure rate is logged and is the hallucination metric. |
| Coach sampling | Temperature is not varied per persona. It is deprecated on current Claude models, the evidence that it acts as a creativity dial does not hold up, and mechanically it scales the whole token distribution, so raising it for a livelier voice raises entropy on the win percentage by exactly as much. Voice comes from exemplars, allowed/banned lexicons, and sentence budgets. Exemplars use deliberately fake, distant content so any leakage is caught by the validator. |
| Coach prompt layout | Three blocks with two cache breakpoints: stable task contract and rules R1–R6; then the per-persona register block with 3–5 exemplars; then the facts JSON and a one-line task, last and closest to generation. Facts go in a user text block, not a tool result, because tool results are treated with deliberate scepticism. |
| Board | `react-chessboard@5.12.1` (MIT). **Not chessground**: its README requires that a site using it release its own source under the GPL. Same reason rules out `chessops`. The board is a real CSS grid with `position:relative` squares, so classification badges are absolutely-positioned children and `squareRenderer` can replace a whole square. Needs a `'use client'` wrapper (the package ships none and uses `useLayoutEffect`); `dynamic(ssr:false)` is not needed. |
| Pieces | Cburnett, taken under its **BSD-3 option**. The Wikimedia Commons file pages carry `{{self|GFDL|migration=relicense|BSD|GPL}}`, so the licence is ours to pick; BSD requires only a copyright notice. react-chessboard inlines this set already, so there is zero integration work. Swappable later via the `pieces` prop to fantasy / spatial / celtic (MIT) or rhosgfx (CC0). Credit line lives on `/about`. |
| Board animation | Piece moves animate with CSS `transform`, never FLIP, since both squares are known analytically. Duration 180 ms `ease-in-out` (chess.com's default; react-chessboard's own default of 300 is too slow). Captures fade the taken piece rather than moving it. Castling needs no special case: diff the piece maps and match each new piece to the nearest missing piece of the same type. `will-change: transform` on pieces and last-move squares. |
| Reduced motion | Honoured, unlike lichess and chess.com, and wired through JS config rather than CSS, because a media query cannot reach a JS-set duration: `animationDurationInMs: reduced ? 0 : 180`, `showAnimations: !reduced`. Decorative motion (badge pops, check flash) is disabled outright; functional feedback is kept. |
| Arrows | One absolutely-positioned SVG over the grid, `inset: 0`, fixed `viewBox="0 0 2048 2048"` so one square is 256 units at any size, `pointer-events: none`. Board flip is folded into the coordinate function, not the SVG. Best-move and threat arrows use `arrowStartOffset: 0.3`. |
| Eval bar | `transform: translate3d(0, N%, 0)` with `transition: transform 1s ease-in`. Never animate `height`, which triggers layout. Centipawns map through the lichess logistic curve, clamped to 5–95% so the losing side keeps a visible sliver. |
| Sound | Off by default, opt-in. Vendored CC0 files only (`uisfx` audio, Freesound CC0 packs, Kenney), with a `SOUND_CREDITS.md` giving per-file URL and SPDX id. **Lichess's default sounds are not free** and several "CC0 chess sound" repos are laundered copies of them. Playback is hand-rolled Web Audio through a `GainNode`, because `HTMLMediaElement.volume` is ignored on iOS Safari. Sound fires only when `ply === prevPly + 1`, so jumps and rewinds are silent. |
| Framework | Next.js 16 App Router, TypeScript strict, Tailwind, pnpm 10, Node 22. Deployed to Vercel Hobby. |
| Responsive | Mobile-first behaviour verified 320–1600px with zero horizontal overflow on every screen. Breakpoints at **1240** (review drops to two columns), **1024** (single column; review reorders to board → coach → notation → nav → accuracy, since the coach is the point on a phone), **860** (game rows become a three-line block, tables stack, grids collapse), **620** (tighter padding, thinner board frame and eval bar, topbar folds to two rows) and **380** (smallest phones). The board is `width:100%; aspect-ratio:1` with the eval bar as a grid sibling so it tracks the board's height exactly — no fixed pixel sizes. Drop targets are computed from the live `getBoundingClientRect()` and the *computed* border width, so a thinner mobile frame does not break dragging; the drag ghost is sized to the current square. Wide tables carry `.tbl-stack`, which turns each row into a block of stacked cells on a phone rather than a sideways scroll. `@media (hover:none)` raises every control to a 42px touch target and disables hover transforms. **No inline `font-size` or `grid-template-columns` on layout elements** — a media query cannot override them, which is how the home grid and the landing headings first broke. |
| Visual identity | **Wood, paper, brass, felt** — the four materials of a chess club, used as roles, not decoration. The page ground is walnut with a real grain (an SVG `feTurbulence` stretched on one axis, `mix-blend-mode: overlay` at .42, one fixed layer behind everything). Every readable surface is a cream paper card laid on it. **Brass** marks what you can act on and is the focus ring; **felt green** confirms (approve, best, cached); **lacquer red** warns (decline, blunder, errors). Committed single-theme: no dark/light toggle, but every colour is painted explicitly rather than inherited. Tokens and every component live in `docs/design/app.html`, screen `#/components`. |
| Type | **Fraunces** for display and headings (variable, `SOFT 20-40 / WONK 1`, optical size tied to the size), **IBM Plex Sans** for all interface text, **IBM Plex Mono** for anything a chess player reads as data — notation, evals, accuracy, eyebrows, column heads, IDs. One characterful serif plus one superfamily: three roles, two families. Accuracy numerals are set in Fraunces at display weight and are the one typographic flourish per screen. |
| Screens | `/` home (username entry + recent games + month summary), `/u/[username]` games (player header, import progress, filters, list), `/g/[gameId]` review, `/login`, `/signup` request access, `/pending`, `/admin` (requests / members / usage), `/settings` (coach, engine, board, account, delete), `/about` credits, plus the public **landing page** shown to logged-out visitors (hero, the same-move-twice comparison, the seven coaches, three steps, what a review contains, invite-only closer). All are built and clickable in `docs/design/app.html` behind a hash router with a design-harness strip that is **not** part of the product. |
| Rules engine | `chess.js@1.4.0` (BSD-2-Clause) for legality, SAN/UCI, FEN. |
| Explore / variations | From **any** position the user can play their own moves and continue for as long as they like — the feature sactherook.com has and a review is not credible without. Legality comes from `chess.js`; the first move that leaves the mainline opens a variation, and a move that *matches* the mainline just steps the review forward. Variations live in component state only: never written to `reviews` or `position_evals`, never in the URL, cleared by "Back to the game", which restores the ply the branch left from. Notation renders the variation as an indented branch under its parent move. |
| Board input | **Pointer Events only** (`pointerdown`/`pointermove`/`pointerup` + `setPointerCapture`) — one code path for mouse, touch and pen. Not HTML5 drag-and-drop (no touch support, and the drag image cannot be styled) and not mouse events. Drag and click-to-move share the same `tryMove(from, to)`. The drop square is computed from the board's `getBoundingClientRect()`, **not** `elementFromPoint`, so the drag ghost cannot intercept the drop. Ghost is a `position: fixed` SVG with `pointer-events: none`; the source square keeps a faded copy. Legal targets are dots, captures a ring, from `moves({square, verbose:true})`. `user-select: none` on the board and `-webkit-user-drag: none` on pieces. |
| Promotion | Needs a real picker (Q/R/B/N) on the destination square before the move is committed. The design preview auto-queens; that is a preview shortcut, not the spec. |
| Arrow policy | Arrows are drawn **only** on a position reached by an inaccuracy, miss, mistake or blunder: green = the move that was better (skipped if that piece is no longer on the from-square), red = the refutation the engine now plays. At every other ply, and while a piece is selected or a variation is open, no arrows. Drawing the side-to-move's own best move in red at an ordinary position reads as a threat and is wrong. |
| Engine payload | Stockfish 16 WASM single-threaded is 562 KB, but its NNUE net (`nn-5af11540bbfe.nnue`) is **38 MB** and is fetched separately at init. That, not the wasm, is the real first-load cost of the browser-side decision: it must be cached (Cache API or a service worker) and served `immutable`, with an explicit "preparing the engine" state on first visit. Confirm the figure for whichever Stockfish build ships. |
| Openings | lichess-org/chess-openings TSV bundled at build; lookup by EPD, walking backwards to last named position. |
| Win% | lichess curve: `win = 50 + 50 * (2 / (1 + exp(-0.00368208 * cp)) - 1)`, cp clamped ±1000, mate → 100/0. |
| Expected points | `EP = win / 100`. |
| Class ladder (EP lost, mover's view) | best < 0.01, excellent < 0.045, good < 0.08, inaccuracy < 0.12, mistake < 0.22, else blunder (WintrChess constants). Mate transitions use explicit tables, not the curve. |
| Special classes | brilliant, great, miss per section 6 rules; book from opening table; checkmate = best. Forced (one legal move) is displayed as best with a "forced" flag, not an eleventh class. |
| Accuracy | lichess: move `103.1668 * exp(-0.04354 * (winBefore - winAfter)) - 3.1669 + 1`, clamp 0–100; game = mean of (stdev-weighted mean over windows clamp(moves/10, 2, 8), weights clamp 0.5–12) and harmonic mean (per-move floored at 10). |
| Estimated rating | ACPL based: `elo = 3100 * exp(-0.01 * acpl)`, then pulled toward the player's known rating: `expectedAcpl = -100 * ln(rating / 3100)`, `estimate = rating * exp(-0.005 * (acpl - expectedAcpl))`. Shown with a ± band. |
| Tests | Vitest for `packages/engine`. Playwright is out of scope for v1. |

## 4. Shared contracts (frozen)

All section writers code against these types. They may add fields to their own
internal types but may not change these.

```ts
// packages/engine/src/types.ts

export type Color = 'w' | 'b';

export type Classification =
  | 'brilliant' | 'great' | 'best' | 'excellent' | 'good'
  | 'book' | 'inaccuracy' | 'mistake' | 'miss' | 'blunder';

/** Score from White's point of view. Exactly one of cp / mate is set. */
export interface Score { cp?: number; mate?: number }

export interface EngineLine {
  multipv: 1 | 2 | 3;
  score: Score;
  pv: string[];            // UCI moves
  depth: number;
  nodes: number;
}

/** Deterministic evaluation of one position. Cached by (fen, nodes, engineBuild). */
export interface PositionEval {
  fen: string;
  nodes: number;           // node budget used, e.g. 1_000_000
  engineBuild: string;     // e.g. "stockfish-18-single-nn-9067e33176e8"
  lines: EngineLine[];     // multipv 1..3, best first
}

export interface MoveAnalysis {
  ply: number;             // 1-based half-move index
  color: Color;            // who moved
  san: string;
  uci: string;
  fenBefore: string;
  fenAfter: string;
  evalBefore: PositionEval;
  evalAfter: PositionEval;
  winBefore: number;       // mover's win% before the move
  winAfter: number;        // mover's win% after the move
  epLoss: number;          // expected points lost, >= 0
  moveAccuracy: number;    // 0..100
  classification: Classification;
  forced: boolean;
  bestMove: string;        // UCI, from evalBefore.lines[0]
  bestLine: string[];      // UCI
  opening?: { eco: string; name: string };
}

export interface KeyMoment {
  ply: number;
  kind: 'blunder' | 'mistake' | 'miss' | 'brilliant' | 'great' | 'left_book';
  severity: number;        // 0..1, used for ordering; 1 = most important
}

export interface PlayerSummary {
  username: string;
  color: Color;
  rating?: number;         // from chess.com PGN header
  accuracy: number;
  acpl: number;
  estimatedRating: number;
  estimatedRatingBand: number;   // ± value
  counts: Record<Classification, number>;
}

export interface Review {
  gameId: string;          // chess.com game id
  engineBuild: string;
  nodes: number;
  moves: MoveAnalysis[];
  keyMoments: KeyMoment[];
  white: PlayerSummary;
  black: PlayerSummary;
  opening?: { eco: string; name: string; lastBookPly: number };
}

/** Verified facts about one move. The coach may only mention what is here. */
export interface MoveFacts {
  ply: number;
  san: string;
  classification: Classification;
  epLoss: number;
  winBefore: number;
  winAfter: number;
  bestMove: string;        // SAN
  bestLine: string[];      // SAN, max 5
  playedLine: string[];    // SAN, engine's reply line after the played move, max 5
  motifs: Motif[];
  materialAfterBestLine: number;   // pawn units, mover's view
  materialAfterPlayedLine: number;
  phase: 'opening' | 'middlegame' | 'endgame';
  opening?: { eco: string; name: string };
  leftBook: boolean;
  threatOfBestMove?: string[];     // SAN line found by null-move probe
  audience: 'beginner' | 'intermediate' | 'advanced';
}

export type Motif =
  | { type: 'hanging_piece'; square: string; piece: string; side: Color; attackers: string[]; defenders: string[] }
  | { type: 'missed_capture'; square: string; piece: string; value: number }
  | { type: 'fork'; by: string; targets: string[] }
  | { type: 'pin'; pinned: string; pinner: string; against: string; absolute: boolean }
  | { type: 'discovered_attack'; mover: string; attacker: string; target: string }
  | { type: 'mate_threat'; line: string[] }
  | { type: 'missed_mate'; line: string[] }
  | { type: 'back_rank_weak'; side: Color }
  | { type: 'trapped_piece'; square: string; piece: string }
  | { type: 'sacrifice'; piece: string; square: string; netMaterial: number }
  | { type: 'only_move'; secondBestEpLoss: number };

export interface CoachText {
  ply: number;
  headline: string;        // <= 60 chars
  whatHappened: string;    // 1–2 sentences
  whyItMatters: string;    // 1–2 sentences
  betterWas: string;       // 1–2 sentences, must name bestMove
  lesson: string;          // 1 sentence
  source: 'llm' | 'template';
  model?: string;
}
```

## 5. Import, data and auth

> Status: **auth and data built** (milestone 1). chess.com import is milestone 2 and
> is not written here yet.

### 5.1 Where the schema diverges from section 4, and why

Section 4 put `role` and `status` in `user_profiles`. **They are on the `user`
table instead.** Better Auth's cookie cache serialises the user record and
nothing else — `setCookieCache` → `parseUserOutput` → core fields plus
`user.additionalFields`. Authorization state anywhere else means `proxy.ts`
cannot read it, so every request would pay a `SELECT` and the proxy would need
a database driver, which the Next docs explicitly warn against.

Split as built:

| Column | Table | Why |
|---|---|---|
| `role`, `status`, `approved_by`, `approved_at` | `user` | authorization; must reach the proxy for free |
| `occupation`, `note`, `chesscom_username`, `audience` | `user_profiles` | content; `note` is free text and the session cookie chunks past ~4KB |

`account.issuer` and the `(issuer, accountId)` unique index are **new in Better
Auth 1.7** and are easy to miss by hand — omitting them breaks sign-up at
`linkAccount`. Regenerate rather than edit: `pnpm dlx auth@1.7.2 generate`
(the CLI moved from `@better-auth/cli`, which is frozen at 1.4.21). The
committed schema was diffed against that output column-for-column.

### 5.2 Local database

`DATABASE_URL` selects the driver. `postgres://…` → Neon over the **WebSocket
`Pool`** (`drizzle-orm/neon-serverless`), never `neon-http`: Better Auth wraps
sign-up in an interactive transaction, which the HTTP driver cannot do.
Anything else, or nothing → PGlite at `.pglite/`, so a fresh clone runs with no
credentials.

**PGlite is single-process, and it does not enforce it.** A second process
opening the same data directory does not fail — it corrupts the store and
aborts the wasm runtime. Two consequences, both load-bearing:

1. `getDb()` is **lazy**. Nothing connects at import. `next build` collects page
   data in five workers that import every route module; eager construction
   failed the build outright.
2. Migrations run from `instrumentation.ts`, once per server process, which
   Next does not call during page-data collection. `pnpm db:migrate` is for
   Neon only. Never query `.pglite/` from a second process while the dev
   server is up.

### 5.3 Auth flow, as built

Sign-up → `status = 'pending'` + verification mail. Unverified sign-in returns
`403 EMAIL_NOT_VERIFIED`. Verified-but-pending can sign in and sees `/pending`.
An address in `ADMIN_EMAILS` is promoted in the `user.create.before` hook, so
it lands `admin`/`approved` at sign-up; `session.create.before` is the backstop
for addresses added later, and lags by up to the cookie-cache window.

`requireEmailVerification: true` **silently turns on sign-up enumeration
protection**: signing up with an address that already exists returns `200` with
a synthetic user and sends no mail. `/signup` must therefore always say "check
your email" and never "account created" or "email already in use".

### 5.4 Gaps section 4 left

- `/reset-password` and `/forgot-password` are missing from the page list. The
  reset link lands on `${baseURL}/api/auth/reset-password/:token`, which
  redirects to the app — without those pages the flow 404s.
- `GET /api/me/profile` cannot require *approved*, or `/pending` cannot render
  "rejected" versus "awaiting approval". `GET` takes a session-only guard;
  `PUT` requires approved.
- Rejection deletes the user's sessions. The cookie cache would otherwise carry
  a stale `approved` for up to its window — the one direction where lag is
  dangerous.

### 5.5 Import (milestone 2)

**The API, as it really is.** `GET /pub/player/{u}` , `/stats`, `/games/archives`,
`/games/{YYYY}/{MM}`. No key, but a default user-agent gets a Cloudflare block,
so requests identify themselves. Every response is cached: a finished month is
immutable and gets a week, the current month five minutes.

Two things the docs do not tell you. **`/stats` returns 404 with an "internal
error" body for some accounts** — reproducibly, for `hikaru` — so ratings fall
back to the value the player carried in their most recent game of each class,
marked with an asterisk in the UI. And **the `eco` field is a URL, not a code**;
the ECO code lives in the PGN's own headers.

`rules === 'chess'` filters out variants, which share the endpoint.

**Columns.** `players` keyed by lowercased username, carrying display spelling,
title, ratings, `archive_count` and `imported_through`. `games` keyed by
chess.com's numeric id from the PGN `Link` header, holding the whole PGN plus
the fields worth querying: both usernames (lowercased, indexed by colour with
`end_time`), ratings, results, ECO, opening, plies, and **chess.com's own
`accuracies` where present** — about a third of games — kept purely so our
scoring can be checked against theirs in milestone 3.

**Opening names** are derived from the ECO URL slug, which appends the moves
that reach the position, either after an ellipsis or after a move number.
`openingName` cuts at whichever comes first; it is unit-tested against the real
shapes, including `-5...O-O`, where naive splitting eats the castling.

**Measured.** Six months of a busy account: 2,750 games fetched, 2,750 stored,
0 skipped, 41s, 6.5MB of table. The import is serial by choice — chess.com asks
for sequential access — and rows are chunked at 100 because each carries a PGN.

**A redirect loop, found and fixed.** The proxy treated *any* session cookie as
proof of being signed in, so a stale cookie bounced the user off `/login` to
`/`, where the server-side guard bounced them back: `ERR_TOO_MANY_REDIRECTS`,
escapable only by clearing cookies. A decoded cookie cache and a merely-present
token are now different questions — the first is authoritative, the second only
stops us redirecting to `/login`.

### 8.1 Design system

Prototype tokens are ported verbatim into Tailwind v4's `@theme` in
`globals.css`, and shadcn's semantic names (`--background`, `--primary`,
`--ring`, …) are remapped onto them so any shadcn component inherits the
identity rather than being restyled one at a time. `--background` maps to
**paper, not wood** — every control sits on a cream card, so an outline button
on `bg-background` would otherwise come out walnut-on-walnut. The wood ground
is painted explicitly on `body`.

Four independent locks keep the single theme honest: no `@custom-variant dark`
declaration (an undeclared variant makes a stray `dark:` utility compile to
*nothing* rather than to a half-inverted control), no `.dark` block,
`color-scheme: light` on `:root` so the browser does not invert native widgets,
and no `next-themes`.

`source('../')` on the Tailwind import is load-bearing: without it class
detection starts at the git root and crawls `docs/design/`, which holds a 140KB
prototype and a vendored chess.js.

Primitives live in `src/components/ui/index.tsx` as `cva` variants — Button
(brass / primary / felt / ghost / danger / onwood), Card, Field, Input,
InputPrefix, Textarea, Select, Chip, Avatar, Notice, Eyebrow, RuleOr,
LinkButton. `LinkButton` exists instead of a Radix-style `asChild` slot; nothing
here needs the polymorphism.

### 8.2 Fonts

`next/font/google` self-hosts all three, so the prototype's `<link>` tags are
gone. Two traps, both verified: Fraunces's `axes` must **not** list `wght`
(next/font throws), and **IBM Plex Mono is not a variable font** on Google —
omitting `weight` throws, so 400/500/600 are enumerated.

### 8.3 Routing and the gate

`typedRoutes: true` means a runtime redirect target needs an explicit
`as Route` cast; the login form's `?next=` is checked for a leading `/` and
rejects `//` so the cast cannot become an open redirect.

Gated pages sit in an `(app)` route group whose layout calls `requireApproved()`
on every render. Auth pages sit in `(auth)`. `/pending` is deliberately outside
both — it needs a session but not approval.

Sign-up always renders "check your email" and never "account created" or
"email already in use", because Better Auth's enumeration protection makes
those two indistinguishable from the client.
